# Шаблон сервиса AI-ассистентов

В монорепозитории три Go-приложения. Клиенты обращаются к gateway по HTTP и WebSocket.

| Сервис | Ответственность | Хранилище |
| --- | --- | --- |
| `api-gateway` | Проверяет пользовательский JWT, передаёт ID владельца в AI, маршрутизирует HTTP и WebSocket | Не хранит данные |
| `auth-service` | Регистрирует пользователей, проверяет пароль, выдаёт и обновляет токены | `auth_db` — пользователи и refresh-сессии |
| `ai-service` | Управляет ассистентами, перепиской, подключениями Telegram и Twilio, блокировками и статистикой | `ai_db` — ассистенты, чаты, сообщения, Twilio и блокировки |

Auth выпускает JWT с `sub`, равным сохранённому `users.id`. При создании ассистента AI записывает этот ID в `assistants.user_id`. Чтение истории и проверка владельца выполняются в AI. Для внешнего API AI сам находит ассистента по его Bearer-токену. Gateway удаляет пришедшие от клиентов заголовки идентификации и передаёт кабинетным маршрутам проверенный ID из JWT.

## Запуск

В корне репозитория создайте `.env` из `.env.example`. В PowerShell это можно сделать командой:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

Задайте отдельные случайные значения для `POSTGRES_PASSWORD`, `AUTH_DB_PASSWORD`, `AI_DB_PASSWORD`, `ACCESS_SECRET` и `REFRESH_SECRET`. Для ответов модели заполните `OPENAI_API_KEY`. Для Telegram нужны `TELEGRAM_WEBHOOK_SECRET` и публичный HTTPS-адрес gateway в `WEBHOOK_BASE_URL`. Для Twilio тот же адрес указывается в `BASE_URL`. Номер, SID и токен Twilio передаются при регистрации соответствующего ассистента.

```sh
docker compose up --build
```

Gateway доступен по адресу `http://localhost:8085`, проверка состояния — `GET /health`. Только gateway публикует HTTP-порт. Приложения доступны друг другу в сети Compose. PostgreSQL доступен локально на `127.0.0.1:5433`. В dev-конфигурации команда `docker compose -f docker-compose.dev.yml up --build` использует свои тома, порт gateway 8080 и порт PostgreSQL 5432. Dev-файлу нужен Docker Compose 2.24.4 или новее.

При первом запуске PostgreSQL создаёт базы `auth_db` и `ai_db` с отдельными ролями `auth_app` и `ai_app`. Каждая роль может подключиться только к своей прикладной базе. При старте приложения применяют встроенные нумерованные SQL-миграции под транзакционной блокировкой. У каждого сервиса свой каталог `internal/modules/database/migrations`.

Для запуска из IDE можно поднять только PostgreSQL командой `docker compose up -d postgres`. В каждом сервисе скопируйте его `.env.example` в `.env` и запускайте `go run .` из каталога сервиса. Укажите пароль его роли в `PGPASSWORD`. У auth и gateway должно совпадать значение `ACCESS_SECRET`. При таком запуске примеры используют порты 8081 для AI, 8082 для auth и 8085 для gateway. Доступ к HTTP-порту AI предназначен для доверенного gateway.

## Как добавлять модуль

- В `internal/modules/<имя>` размещаются операции модуля и его зависимости. Для работы с таблицами сервиса SQL и миграции лежат в `internal/modules/database`.
- `main.go` загружает конфигурацию, создаёт долгоживущие модули и собирает `internal/app.App`. Здесь же он отвечает за закрытие пула PostgreSQL.
- `internal/api` получает `App` при регистрации маршрутов. Конструктору обработчика передаются модули, нужные конкретному маршруту. Например, в auth обработчик получает модуль авторизации, а сам модуль получает хранилище при запуске.

## Возможности

| Сценарий | Точка входа через gateway |
| --- | --- |
| Регистрация, вход, обновление и завершение сессии | `POST /auth/register`, `/auth/login`, `/auth/refresh`, `/auth/logout` |
| Создание ассистента для API, Telegram или Twilio | `POST /ai/webhooks/{api,telegram,twilio}/register` |
| Переписка по API | `POST /webhooks/telegram` с API-токеном ассистента и полем формы `user_message` |
| Настройки ассистента и список чатов | `/ai/assistants/…`, `/ai/chats/…` |
| История диалога через WebSocket | `/ai/websocket/get_conversation?chat=<chat_id>` |
| Глобальный список блокировки SMS-контактов | `GET` и `POST /ai/blocked-customers/` |
| Статистика по ассистенту | `GET /ai/analytics?assistant_id=<id>` |

Для кабинета передавайте access-токен в `Authorization: Bearer …`. При регистрации Telegram-ассистента AI устанавливает callback. При регистрации Twilio-ассистента AI возвращает URL для входящих SMS. Статистика использует чаты в PostgreSQL, включая признак завершения `is_end`. Настройки LLM берутся из конфигурации ассистента.

## Перенос данных из общей базы

Для нового проекта достаточно обычного запуска. Для существующей установки есть [импорт из прежней схемы](deploy/postgres/import_legacy.py). Нужны Python 3 и клиент PostgreSQL `psql` в `PATH`. Подготовьте резервную копию, прекратите запись в старую базу и не направляйте пользовательский трафик в новые приложения до завершения проверки. Один раз запустите auth и AI для создания пустых таблиц. Чтобы сохранить действующие сессии, укажите прежние `ACCESS_SECRET` и `REFRESH_SECRET`.

Пример PowerShell использует имена подключений, настроенные в libpq. Можно также задать URL подключения и использовать `pgpass` для паролей.

```powershell
$env:LEGACY_DATABASE_URL = 'service=legacy'
$env:TARGET_DATABASE_URL = 'service=auth_target'
python deploy/postgres/import_legacy.py auth
$env:TARGET_DATABASE_URL = 'service=ai_target'
python deploy/postgres/import_legacy.py ai
```

Каждый запуск переносит свою группу таблиц в пустую БД одной транзакцией и сохраняет исходные ID. После ошибки можно повторить перенос соответствующей группы. Проверьте числа записей, вход со старым паролем, список ассистентов и историю сообщений перед переключением gateway. Скрипт читает только используемые столбцы исходной базы. Ручная [очистка прежней схемы](deploy/postgres/legacy_cleanup.sql) для импорта не требуется.

У email в новой базе есть ограничение уникальности. Если в источнике есть дубли, их нужно разобрать перед переносом. Refresh-токены без существующего аккаунта пропускаются с указанием количества. Если у ассистента отсутствует владелец, импорт AI остановится для уточнения принадлежности. Это важно для установок, где прежняя регистрация могла выдать JWT с другим ID.

## Проверки

У каждого сервиса свой `go.mod`. Из каждого каталога запускайте `go test ./...` и `go vet ./...`. Для интеграционных тестов PostgreSQL укажите `AUTH_TEST_DATABASE_URL` в auth и `TEST_DATABASE_URL` в AI. Используйте тестовые базы с правами на создание временных схем и данных.
